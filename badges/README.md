# Neuro Forge Badges

This directory defines the Neuro Forge badge system.

There are two badge categories:

1. Neuro Forge static/custom badges stored in this repository.
2. GitHub dynamic badges generated as Markdown URLs.

Do not store dynamic GitHub status badges locally. Generate them from verified repository data only.

## Custom Badges

Stored files:

```markdown
![Neuro Forge](badges/generated/neuroforge.svg)
![AI-assisted](badges/generated/ai-assisted.svg)
![Atypical ThinkR / 0SEC WorkR](badges/generated/0sec-workr.svg)
```

Required custom badges:

| Badge | Source | Purpose |
| --- | --- | --- |
| Neuro Forge | `badges/generated/neuroforge.svg` | Marks a project aligned with the Neuro Forge standard. |
| AI-assisted | `badges/generated/ai-assisted.svg` | Declares transparent AI-assisted development. |
| Atypical ThinkR / 0SEC WorkR | `badges/generated/0sec-workr.svg` | Marks the Neuro Forge operating philosophy. |

The `Neuro Forge pending` variant is generated from `badges/templates/badge-template.svg` by changing the right-side text and status class. It is not stored as a separate file.

## Generator

Use:

```sh
scripts/generate-badges.sh path/to/project
```

The generator:

- reads `neuroforge.yml`;
- detects the GitHub repository from `neuroforge.yml` or `git remote`;
- detects platform metadata;
- detects workflow files when present;
- detects license files;
- runs `scripts/check-neuroforge-compliance.sh`;
- writes `build/neuroforge-badges.md`;
- writes `build/neuroforge-badges.json`;
- updates `README.md` only between `NEUROFORGE_BADGES` markers when they exist.

The generator omits dynamic badges when required data is not available.

## Dynamic Badges

Dynamic badges must be generated from verified repository metadata.

Examples:

```markdown
![Release](https://img.shields.io/github/v/release/OWNER/REPO?label=release&color=111111&labelColor=f5f5f5)
![Build](https://img.shields.io/github/actions/workflow/status/OWNER/REPO/WORKFLOW.yml?label=build&color=111111&labelColor=f5f5f5)
![Tests](https://img.shields.io/github/actions/workflow/status/OWNER/REPO/TEST_WORKFLOW.yml?label=tests&color=111111&labelColor=f5f5f5)
![License](https://img.shields.io/github/license/OWNER/REPO?label=license&color=111111&labelColor=f5f5f5)
![Language](https://img.shields.io/github/languages/top/OWNER/REPO?label=language&color=111111&labelColor=f5f5f5)
![Platform](https://img.shields.io/badge/platform-PLATFORM-111111?labelColor=f5f5f5)
![Maintained](https://img.shields.io/github/last-commit/OWNER/REPO?label=maintained&color=111111&labelColor=f5f5f5)
```

Rules:

- `release`: use the latest GitHub release only.
- `build`: use the primary GitHub Actions workflow.
- `tests`: use the test workflow.
- `license`: use the actual repository license.
- `language`: use GitHub top-language data.
- `platform`: use `neuroforge.yml`.
- `maintained`: use recent GitHub activity or project metadata.
- Never invent a value. Use `pending` only when a value is intentionally unknown.

## README Integration

Recommended order:

1. Neuro Forge;
2. release;
3. build;
4. tests;
5. platform;
6. language;
7. license;
8. AI-assisted.

`Atypical ThinkR / 0SEC WorkR` may be displayed as a brand signature directly below the technical badge row.

Use markers for generated README sections:

```markdown
<!-- NEUROFORGE_BADGES:BEGIN -->
<!-- Generated by scripts/generate-badges.sh -->
<!-- NEUROFORGE_BADGES:END -->
```

## GitHub Pages Integration

GitHub Pages should consume `build/neuroforge-badges.json` or an equivalent generated artifact. Do not duplicate badge status values manually in project pages.
